# POSEIDON — засвоєння даних ансамблевим методом (Python)

Python-версія робочого процесу **засвоєння даних (data assimilation)** для моделі перенесення радіонуклідів **POSEIDON**. Код є перенесенням (реалізацією) оригінального набору the model-скриптів (`01.RunKFS/model/*.m`) на Python.

Робочий процес реалізує **ансамблевий фільтр / згладжувач Калмана** (ensemble Kalman filter / smoother): він коригує вектор стану моделі POSEIDON за спостереженнями, обчислює аналіз у **просторі логарифмів концентрацій**, записує оновлений стан назад у файли `Initconc.dat`, після чого модель продовжує прогноз до наступної дати аналізу.

## Загальний опис методу

**Область.** Море (Чорне море) розбите приблизно на 50 боксів (розрахункових комірок) по горизонталі та до 4 вертикальних рівнів. Геометрія боксів (межі по широті/довготі, кількість рівнів, центри мас) зберігається у файлах `config/*.xlsx`.

**Ансамбль.** «Ансамбль» — це набір із 24 прогонів моделі POSEIDON (каталоги `NN.hydrolXdepY`), що відрізняються сценаріями гідрології та осадження. Розкид ансамблю використовується для оцінки коваріації похибок прогнозу.

**Простір логарифмів.** Аналіз виконується для **натуральних логарифмів концентрацій**. Концентрації радіонуклідів мають логнормальний розподіл, тому в лог-просторі задача регресії стає зручнішою, а оновлені концентрації не можуть стати фізично неможливими (від'ємними).

**Крок аналізу (для однієї дати):**

1. Зчитати спостереження з файлу `<дата>.dat`.
2. Прив'язати кожне спостереження до боксу та вертикального рівня (геолокація точки).
3. Зчитати стани членів ансамблю з виходів POSEIDON (`lastconc.xls`) і сформувати вектор стану та матрицю відповідності спостережень **H**.
4. Оцінити коваріаційну матрицю **C** похибок прогнозу за ансамблем.
5. Застосувати **локалізацію** коваріації: послабити далекі кореляції залежно від горизонтальної та вертикальної відстані (а у згладжувачі — ще й від різниці в часі). Окремі бокси (Середземне, Мармурове, Азовське моря тощо) роблять незалежними.
6. Записати задачу аналізу як **метод найменших квадратів**: об'єднати доданок узгодження зі спостереженнями (`invO2·H`, зважений на похибку спостережень) із фоновим доданком, отриманим з LDL-розкладу оберненої коваріації `C⁻¹`. Розв'язати `least-squares` для кожного члена ансамблю з **збуреними спостереженнями** (стохастичний EnKF).
7. Записати результат назад у файли перезапуску `Initconc.dat` та підсумувати у `out_<дата>.xlsx`.

**Фільтр vs згладжувач.**
- `main_LN` — **фільтр**: використовуються лише спостереження на дату аналізу.
- `main_KSF_LN` — **згладжувач**: спільно засвоюються спостереження з кількох дат (додається часова локалізація), а аналіз будується для останньої дати в наборі.

**Зовнішній цикл** (`run_LN_KSF3`, `run_NODA`, `runall_LN`): для кожної дати виконати аналіз, скопіювати файли перезапуску вперед, запустити POSEIDON для прогнозу до наступної дати, порівняти з спостереженнями (`main_obsproconly`) і повторити для всієї послідовності дат 1986–2007.

## Верифікація перенесення з the model

Код створено з the model на Python пофункційно (кожен файл `.m` має відповідник `.py`). 

**Спосіб верифікації.** Єдине джерело випадковості в алгоритмі — **збурення спостережень** (observation perturbations): у формуванні `obs_noise` до кожного спостереження додається `(1/invO2)·randn`. Оскільки генератори випадкових чисел the model (`randn`) і NumPy (`np.random.randn`) дають **різні** послідовності навіть за однакового зерна, пряме побітове порівняння з увімкненою випадковістю неможливе.

Тому для верифікації **збурення спостережень були проініціалізовані нулями в обох програмах** (у the model і в Python). Після обнулення випадкової компоненти обидві реалізації стають повністю детермінованими: усі члени ансамблю отримують однакові (незбурені) спостереження, і різняться лише своїм фоновим станом. За таких умов **the model- і Python-версії дали однакові кінцеві результати**, що підтверджує коректність перенесення обчислювального ядра (геолокація спостережень, побудова `H`, оцінка та локалізація коваріації, LDL-розклад і розв'язок найменших квадратів).

> **Примітка.** У робочих (не верифікаційних) прогонах збурення спостережень залишають випадковими. Тоді Python-версія відтворювана **в межах Python** (однакове зерно `np.random.seed` → однаковий результат), але не збігається побітово з the model через різні генератори випадкових чисел.

Додатково детермінований «фронтенд» перевірено окремо: вихід `obs_vs_poseidon` для дати `1986.75` **точно** (до 0.0) збігається з історичним файлом the model `out_1986.75.xlsx` (аркуш `obs`).

## Структура репозиторію

```text
poseidon-ensemble-da/
  bin/
    Poseidon4.exe               # виконуваний файл моделі POSEIDON

  config/
    Box_surfareas.xlsx          # геометрія боксів (базова)
    Box_surfareas_with_centers.xlsx  # геометрія + центри мас боксів (для локалізації)

  measurements.exp2/
    <дата>.dat                  # файли спостережень

  src/
    *.py                        # увесь код Python

  DAruns/
    01.RunKFS/
      templates/                # hydrol-каталоги, куди пишуться оновлені Initconc.dat
      outputs/                  # допоміжні виходи (out_*.xlsx, obs2pos.mat, obs_pos.xls)
      1986.75/  1987.5/  ...    # робочі каталоги прогонів POSEIDON за датами
```

## Призначення каталогів

| Каталог | Призначення |
|---|---|
| `bin/` | Виконуваний файл моделі `Poseidon4.exe`. |
| `config/` | Статичні метадані боксів: межі по широті/довготі, вертикальна структура, центри мас. Використовуються для прив'язки спостережень і локалізації. |
| `measurements.exp2/` | Файли спостережень `<дата>.dat`. |
| `src/` | Код Python (усі модулі робочого процесу). |
| `DAruns/01.RunKFS/templates/` | Шаблонні hydrol-каталоги, куди записуються оновлені файли `Initconc.dat`. |
| `DAruns/01.RunKFS/<дата>/` | Робочі каталоги прогонів POSEIDON для кожної дати. |
| `DAruns/01.RunKFS/outputs/` | Допоміжні виходи Python: `out_<дата>.xlsx`, `obs2pos.mat`, `obs_pos.xls`. |

## Опис файлів коду

### Точки входу (головні скрипти)

| Файл | Що робить |
|---|---|
| `main_LN.py` | **Аналіз для однієї дати** (фільтр). Повний крок EnKF: спостереження → коваріація → локалізація → розв'язок найменших квадратів → запис `Initconc.dat`. |
| `main_KSF_LN.py` | **Аналіз-згладжувач для кількох дат**. Спільно засвоює спостереження з кількох дат із часовою локалізацією; аналіз для останньої дати. |
| `main_obsproconly.py` | **Лише обробка спостережень і діагностика** (без аналізу): зіставляє прогноз ансамблю зі спостереженнями і пише `out_<дата>.xlsx`. |
| `runall_LN.py` | **Повний послідовний цикл** аналіз–прогноз по всіх датах (варіант лише з фільтром `main_LN`). |
| `run_LN_KSF3.py` | Повний цикл із **комбінацією фільтра і згладжувача** (для деяких дат — `main_KSF_LN`) та вікном ±3 місяці. |
| `run_NODA.py` | Контрольний цикл **без засвоєння даних** (No DA): лише прогноз і порівняння зі спостереженнями. |

### Обчислювальне ядро

| Файл | Що робить |
|---|---|
| `obs_vs_poseidon.py` | Зчитує `<дата>.dat`, прив'язує спостереження до боксів/рівнів, усереднює спостереження в межах боксу, повертає вектор спостережень і посилання на бокси. |
| `locate_point3D.py` | Визначає, у який бокс і на який рівень потрапляє точка з координатами (довгота, широта, глибина). |
| `box_levs.py` | Повертає кількість вертикальних рівнів у кожному боксі (жорстко зашита конфігурація). |
| `IJ_Lind.py` | Будує відповідність між лінійним індексом вектора стану `L` та парою (бокс `i`, рівень `j`) — для одиночної дати. |
| `IJT_Lind.py` | Те саме, але з урахуванням **часу** (бокс, рівень, дата) — для згладжувача. |
| `init_Hmatr.py` | Будує матрицю відповідності спостережень **H** (спостереження → компонента стану) для однієї дати. |
| `init_Hmatr_T.py` | Будує **H** із урахуванням часового індексу — для згладжувача. |
| `Box_Neighbors.py` | Матриця сусідства боксів (жорстко зашита топологія). *У поточному коді результат не використовується — успадковано з the model.* |
| `Dist_geocords.py` | Відстань між двома точками за географічними координатами (у метрах). |
| `regularize_Covmatr.py` | Проста регуляризація коваріації: робить виключені бокси незалежними. |
| `regularize_Covmatr_analit.py` | Локалізація коваріації за **горизонтальною і вертикальною** відстанню (аналітична функція згасання). |
| `Tregularize_Covmatr_analit.py` | Локалізація за **горизонтальною, вертикальною і часовою** відстанню — для згладжувача. |
| `read_poseidon.py` | Читає вихідний файл POSEIDON (`lastconc.xls`): концентрації по боксах/рівнях, заголовок, підвал, осади. |
| `write_poseidon.py` | Записує файл у форматі POSEIDON (`Initconc.dat`) для перезапуску моделі. |

### Інфраструктура

| Файл | Що робить |
|---|---|
| `paths.py` | Централізовані шляхи до каталогів і файлів проєкту. |
| `model_compat.py` | Шар сумісності з the model: читання/запис Excel, `least-squares`, запуск `.exe`, копіювання файлів, друк у стилі the model. |
| `poseidon_runtime.py` | Запуск `Poseidon4.exe` у hydrol-каталогах і копіювання `lastconc.xls` → `Initconc.dat`. |

## Формати вхідних даних

**`measurements.exp2/<дата>.dat`** — текстовий файл спостережень. Перший рядок — заголовок; далі 4 стовпці чисел, з яких використовуються: стовпець 2 — довгота, стовпець 3 — широта, стовпець 4 — виміряне значення. Глибина в поточному експерименті фіксована (поверхневі виміри).

**`config/Box_surfareas_with_centers.xlsx`** — аркуш `Sheet1` містить (без рядка-заголовка) числові дані по боксах: номер боксу, глибина, об'єм, площа, межі широти/довготи, кількість рівнів, а також **центри мас боксів** (стовпці 10–11), потрібні для локалізації. Окремий аркуш `header` містить лише текстові підписи стовпців.

## Вихідні дані

**У `DAruns/01.RunKFS/templates/`:**
- оновлені `Initconc.dat` (файли перезапуску моделі).

**У `DAruns/01.RunKFS/outputs/`:**
- `out_<дата>.xlsx` — підсумки аналізу (аркуші `obs`, по одному на кожен hydrol-каталог, та `Ens`);
- `obs2pos.mat` — проміжні дані прив'язки спостережень;
- `obs_pos.xls` — діагностика спостережень.

**У кожному hydrol-каталозі після прогонів POSEIDON:**
- `lastconc.xls`, `concsed.txt`, `concwat_*.txt`, `concbiol_*.txt`, `mat.out`.

## Як користуватися

Встановити залежності:

```bash
pip install -r src/requirements.txt
```

Аналіз для однієї дати (фільтр):

```bash
python src/main_LN.py 1986.75
```

Аналіз-згладжувач для кількох дат:

```bash
python src/main_KSF_LN.py 1988.625 1988.5
```

Повний послідовний цикл:

```bash
python src/runall_LN.py
```

Лише діагностика спостережень:

```bash
python src/main_obsproconly.py 1987.5
```

> **Крок прогнозу** потребує `Poseidon4.exe`. На Linux/macOS запуск відбувається через `wine` (має бути встановлений). Модулі аналізу (`main_LN`, `main_KSF_LN`, `main_obsproconly`) працюють без `.exe`.
